# Phase 2 shape and shadow ownership

Issue: extension-repository #1663

Source baseline: site commit `b8821c1`

## Measurement convention

The issue's original line-oriented inventory reported 22 non-token radius lines
and 29 non-token shadow lines at the production baseline. A declaration parser
against the Phase 1 source baseline records:

| Property | Total declarations | Existing semantic declarations | Non-semantic declarations |
|---|---:|---:|---:|
| `border-radius` | 69 | 48 | 21 |
| `box-shadow` | 38 | 26 | 12 |

The line and declaration counts differ because several shadow values span
multiple physical lines. The post-migration ledger below uses declaration
counts and is generated by:

```sh
node scripts/audit-phase2-light.mjs --ledger
```

| Decorative cue | `--shadow-decorative` | `2px 2px` | Theme effect; Phase 3 may override |
| Action depth | `--shadow-action-rest`, `--shadow-action-hover`, `--shadow-action-press` | `5px 5px` → `3px 2px` | Theme effect; Phase 3 may override |
| Press motion | `--motion-duration`, `--motion-easing` | `120ms ease-out` | Shared interaction; Phase 3 must not override |
| Spacing | `--spacing-xs` through `--spacing-hero` | Existing Phase 0 rhythm retained | Shared layout; Phase 3 must not override |
| Typography hierarchy | `--font-*`, `--font-size-*`, `--line-height-*`, `--letter-spacing-*` | Lora / Raleway / Space Mono hierarchy retained | Shared type; Phase 3 must not override |

Phase 3 may change colors and shadow rendering by semantic role. It must not
change radii, spacing, type hierarchy, target size, or motion timing.

## Motion allowlist

Interactive shadow/transform transitions are `120ms`; all other interactive
transitions are at most `300ms`. Movement-producing hover rules occur only
inside `@media (hover: hover)`. `:active` remains available to pointer,
keyboard, and touch. The global reduced-motion block removes animation and
transition duration, and explicit overrides remove press transforms while
retaining an instant state shadow. The explicit reset covers CTA, interactive
accordion, both zoomable media surfaces, the floating template edge control,
and the welcome reveal list.

At `≤640px`, both template view toggles, previous/next controls, and numeric
inputs are at least `44px` high and wide where applicable. At `≤480px`, the
viewer bar uses the same 16px negative inset as the container and does not add
the historical 8px document overflow.

Longer existing effects are one-shot decorative/progressive-enhancement cues:

- `fadeUp` landing entrances (`0.8s`);
- section reveal transition (`0.6s`);
- `edge-arrow-hint` discoverability cue (`1.5s`);
- welcome `stagger-in` entrance (`0.5s` plus staged delays).

They do not encode interaction state and are all disabled by the global
`prefers-reduced-motion: reduce` contract.
