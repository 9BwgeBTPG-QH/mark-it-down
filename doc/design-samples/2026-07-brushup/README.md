# July 2026 brush-up decision lab

Standalone Phase 0 comparison artifact for
[`chorme_mark-it-down#1661`](https://github.com/9BwgeBTPG-QH/chorme_mark-it-down/issues/1661).
It is stored under `doc/`, outside the GitHub Pages `docs/` output, and does not
change the production design source of truth (`DESIGN.md` and
`app/original.css`).

## Run locally

From the website repository root:

```bash
python3 -m http.server 4173 --bind 127.0.0.1 \
  --directory doc/design-samples/2026-07-brushup
```

Open <http://127.0.0.1:4173/>.

The artifact uses only local HTML, CSS, JavaScript, and WOFF2 files. Its CSP
blocks remote scripts, styles, fonts, images, and objects. Do not evaluate it
with `file://`; font loading and CSP behavior should be checked through the
local HTTP server.

## Fixed comparison contract

- Change one decision axis at a time. The selected radio value changes only
  the named treatment or information architecture.
- S3b is the issue-mandated frame treatment bundle (radius + border), and S5a
  is the issue-mandated status treatment bundle (pill + its box styling).
  Those tokens co-vary inside their named component, but no other sample
  property changes. Score each bundle as one gestalt; do not attribute the
  result to an individual CSS token.
- Shared controls switch all samples between EN/JA, desktop/mobile canvas,
  normal/reduced motion, and self-hosted/fallback fonts.
- Native radios, checkboxes, buttons, and links keep the artifact keyboard and
  touch operable.
- Focus uses a 3 px high-contrast ring with 3 px offset.
- Pointer hover motion is behind
  `@media (hover: hover) and (pointer: fine)`.
- Active states remain available to touch and keyboard users.
- Motion is 120–220 ms, never above the 300 ms project cap.
- `prefers-reduced-motion: reduce` and the simulation control suppress movement.

| Axis | Changed variable | Options |
|---|---|---|
| S1 | Font on real mono surfaces | current fallback, Space Mono, JetBrains Mono, Geist Mono |
| S2 | Heading font only | current Lora, Space Mono, JetBrains Mono, Geist Mono |
| S3a | Card shadow only | current layered shadow, hard 6 px offset |
| S3b | Card radius and border only | current 10 px/subtle, 3 px/solid |
| S3c | Canvas background only | current flat cream, 24 px grid |
| S4 | Dark accent family only | extension `#60a5fa`, signal blue `#4d9fff`, warm amber |
| S5a | Status badge shape only | pill, unboxed label |
| S5b | CTA shape only | pill, 4 px corner |
| S6a | Motion grammar only | 120 ms press, 220 ms glow |
| S6b | Theme information architecture only | system-only, explicit 3 options, compact cycle |

S6a applies each motion grammar to both a light and dark control surface. This
keeps palette from becoming a second changed variable.

The S6a PNG files document the fixed framing and selected grammar, not elapsed
time. Judge motion in the live artifact: **Replay motion** exercises both
surfaces, and each sample button replays through its native click path so mouse,
touch, Enter, and Space use the same feedback. Static images alone are not
valid evidence for the S6a decision.

The production fallback intent is preserved:

- Lora → Georgia, serif, matching the current production token.
- Raleway → `-apple-system`, `BlinkMacSystemFont`, sans-serif, matching the
  current production token.
- Mono candidates for Japanese glyphs → `Yu Gothic`,
  `Hiragino Kaku Gothic ProN`, sans-serif.
- The current mono control and forced-fallback mode → `ui-monospace`,
  `SFMono-Regular`, Consolas, `Liberation Mono`, monospace.

The candidates are Latin fonts. Japanese glyphs therefore resolve through the
documented Japanese fallback; mixed EN/JA strings are intentional test content.
Use the **Force fallback** control, or append `?fonts=fallback`, to verify the
font-load failure path without renaming assets.

## Reproducible states and screenshots

The following query parameters make a decision state reproducible:

```text
?axis=s4&variant=amber&lang=ja&viewport=mobile&motion=reduce&fonts=fallback&capture=1
```

- `axis`: `s1`, `s2`, `s3a`, `s3b`, `s3c`, `s4`, `s5a`, `s5b`, `s6a`, `s6b`
- `variant`: one of the options in `app.js` `axisOptions`
- `lang`: `en` or `ja`
- `viewport`: `desktop` or `mobile`
- `motion`: `reduce` to force reduced motion
- `fonts`: `fallback` to force local fallbacks
- `capture=1`: hide unrelated experiments and lab chrome

Run `./capture-screenshots.sh` to generate an EN desktop and JA mobile image
for every option under `screenshots/`. The script requires `google-chrome` or
`chromium`, Python 3, `curl`, and an unused local port (default `4173`). Before
capturing, it removes only the 52 filenames it owns; a run succeeds only after
all 52 outputs have been recreated as non-empty files.

## Manual verification checklist

- At browser widths `1280 × 900` and `390 × 844`, confirm no horizontal
  document overflow and that each preview remains readable.
- Switch every axis radio and confirm only its named property or IA changes.
- Switch EN/JA and inspect headings, status, keyboard shortcut, changelog, code,
  and mixed-script line breaks.
- In DevTools **Rendered Fonts**, confirm the selected local font on Latin text
  and the documented system fallback on Japanese glyphs.
- Toggle **Force fallback** and confirm the header health state changes from
  `5/5 loaded` to `Fallback forced`.
- Navigate only with Tab, Shift+Tab, Space, and Enter. Confirm every control is
  reachable and the 3 px focus ring remains visible.
- Check S6a using hover-capable pointer, keyboard activation, and touch
  emulation. Use both **Replay motion** and the sample buttons. Then repeat
  with OS reduced motion and the simulation checkbox. Record this live check;
  the S6a PNGs cannot prove duration or reduced-motion behavior.
- For S6b, verify system-only exposes the effective state, explicit controls
  select all three states, the compact control announces its current and next
  state, and an OS theme change updates the System effective state.
- Complete [`decision-record.md`](./decision-record.md) before Phase 1 changes
  production tokens.

## Non-goals

- No production site source, build output, SEO metadata, or deployment files
  are changed.
- No selection is made by this artifact. The final gate is the user's rubric
  decision recorded in `decision-record.md`.
- The artifact does not persist theme selection; persistence belongs to the
  Phase 3 production state machine after S6b is decided.
